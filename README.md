# CameraSimulator

深绿色的 Windows 相机定制与摄影模拟工作室，按选定的第 3 款界面实现。

## 直接使用

解压 `release/CameraSimulator-1.0.0-win-x64.zip`，双击其中的 `CameraSimulator.exe`。保留 EXE 同目录的资源文件；运行不需要 Node.js、Blender、网络连接或账户。当前交付为 Windows x64 便携版，未申请代码签名。

1. 在「身份」填写品牌和型号；可选配色、握柄材质和铭文颜色。
2. 在「传感器」选择画幅或输入尺寸，在「镜头」填写实际焦距。
3. 在「曝光」填写 ISO、快门与光圈的上下限。快门支持 `1/8000` 和秒数。
4. 点击「确定并补齐参数」。所有关键项必须由用户输入或主动选择示例；像素、叶片数、初始白平衡与对焦、噪声参数可以留空。结果页区分自动与手动值，手动值不会被覆盖。
5. 进入「拍摄模拟」，选择静物、夜景或运动场景。滑块或精确输入都能调节参数；精确输入按 Enter 或离开输入框后生效。点击场景主体对焦。
6. 点击「拍摄并保存 PNG」。照片不含界面叠加，长边 1600 px，宽高比跟随传感器，另一边按整数像素取整。

左侧配置区可独立滚动。三维视图支持拖动、滚轮、前后顶部视角、自动旋转和三种灯光。顶部文件图标可导入、导出相机 JSON 配置；草稿自动保存，正常关闭前会等待最新草稿写入。

## 参数和自动补齐

| 参数 | 支持范围 / 默认规则 |
| --- | --- |
| 品牌、型号 | 必填，各 24 字符以内，支持中文 |
| 传感器宽、高 | 分别 0.1–200 mm |
| 实际焦距 | 0.5–2000 mm |
| 光圈能力 | f/0.1–f/256，最小 f 值 ≤ 最大 f 值 |
| ISO 能力 | 1–10,000,000，整数，低值 ≤ 高值 |
| 快门能力 | 1/1,000,000–3600 秒，短曝光 ≤ 长曝光 |
| 有效像素 | 0.1–1000 MP；留空按传感器面积 / 36 推算 MP 并限制范围 |
| 光圈叶片 | 3–16 片；默认 9 片 |
| 初始白平衡 | 1000–40000 K；默认 5500 K |
| 初始对焦 | 0.05–10000 m，并大于焦距；默认至少 4 m |
| 读取噪声 | 0.1–100 e⁻；默认 2.4 e⁻ |
| 满阱容量 | 100–1,000,000 e⁻；默认 45000 e⁻ |

自动补齐有确定规则，不调用云端 AI。更改画幅后，自动生成的像素数会重新计算；手动像素数会保留。修改相机能力后再次确认，已有拍摄参数会限制到新范围并提示。

## 三维与成像边界

- 机身是原创 Blender 网格资产，包含握柄、拨盘、热靴、后背屏幕、镜头玻璃等结构。前端采用实时 PBR、HDR 环境光、阴影和生成的蒙皮纹理。它是可旋转的三维模型；造型固定，铭文、材质和光圈开口可变化。
- 这是实时概念相机工作室，模型的外观尺寸不随传感器/焦距做机械重建，也不提供可制造性验证或 CAD 导出。
- 视角由实际焦距和传感器尺寸计算；曝光使用 `EV100 = log2(N² / t) - log2(ISO / 100)`；景深和弥散圆使用薄透镜近似。场景 EV 是教学用设定，未作真实测光标定。
- 景深使用深度缓冲后处理，噪声采用光子/读取噪声近似；白平衡为 RGB 近似，不包含特定厂商色彩科学、完整光谱和镜头像差。不是实验室级传感器仿真或光学光线追踪。
- 运动预览最多 8 个时间样本，导出 32 个，极慢快门可能出现离散重影；实时景深模糊半径最多 45 px。极端概念参数会超出精确视觉表现范围，视角限制为 0.1°–175°。
- 输出像素尺寸与用户定义的传感器 MP 分开：MP 影响像素间距和噪声估算，PNG 的固定长边用于保证交互速度。

## 源码运行与构建

已在 Node.js 24、Windows 11 x64 上构建。首次安装开发依赖需要网络。

```powershell
npm ci
npm run dev -- --host 127.0.0.1 --port 5173 --strictPort
# 在另一个终端中：
npm run desktop:dev
```

```powershell
npm run typecheck
npm test
npm run package
```

`npm run package` 会先执行类型检查、参数/摄影计算测试和前端构建，再输出 Windows ZIP。Electron 使用本地已安装的运行时。若安装时跳过了 Electron 安装脚本，可执行 `node node_modules/electron/install.js`。

| 路径 | 用途 |
| --- | --- |
| `src/camera.ts` | 配置结构、校验、自动补齐、摄影计算 |
| `src/App.tsx` / `src/studio.css` | 定制界面、草稿、确认流程 |
| `src/CameraViewer.tsx` | 三维机身、材质和实时铭文 |
| `src/Simulation.tsx` | 场景、曝光、景深、噪声、运动采样、直方图 |
| `electron/` | 隔离的桌面窗口、文件对话框与原子草稿写入 |
| `assets-source/CameraSimulator.blend` | 可编辑原始模型，纹理已打包 |
| `assets-source/build_camera.py` | 可重建模型的 Blender 脚本 |
| `design/` | 选定设计、验证截图、实际导出样例 |
| `design-qa.md` | 视觉与交互验收记录 |

模型可在 Blender 中直接编辑。重新生成示例命令：

```powershell
& 'E:\Blender\blender.exe' --background --factory-startup --python assets-source\build_camera.py
```

开发环境未启用 React StrictMode 的双重挂载，以避开 React Three Fiber 9.7.0 的开发态 Canvas 上下文问题（[上游问题](https://github.com/pmndrs/react-three-fiber/issues/3863)）。生产构建不依赖开发服务器。字体为 Windows 系统字体，不向外部字体服务发送请求。

## 数据位置

Windows 草稿位于 Electron 的用户数据目录（通常为 `%APPDATA%\camerasimulator\draft.json`）。写入采用同目录临时文件再重命名；JSON 配置与 PNG 保存在用户所选的位置。不提供云同步、登录或后台上传。

资源来源见 `ASSET-LICENSES.md`。
